# 三、P0：精确定位接触恢复11/12中的失败原因

V2接触恢复12次专项中，11次通过，1次失败。

失败发生在Actor续行期间，已经完成的第一件装配被破坏。

必须首先定位这个真实失败案例。

### 3.1 完整提取失败轨迹

从现有物理日志中恢复：

- 进入接触恢复前10步。
- 恢复过程全部控制步。
- 恢复完成至交还控制权。
- 交还后至少20个Actor控制提议；如果提前终止，记录全部实际执行步和终止时刻。

每一步必须记录：

1. 当前任务阶段。
2. A/B参考索引。
3. 双臂末端位置、姿态及速度。
4. 双臂实际抓取状态。
5. piece_1、piece_2和base的位置及姿态。
6. `first_piece_assembled`真实指标。
7. 物体接触图与接触力。
8. Actor原始14维提议动作。
9. 动作投影后的14维执行动作。
10. 当前控制模式及接管来源。
11. 预测风险、预测物体位移及实际位移。
12. 发生干预、拒绝、交还及Safe_Stop的原因。

重点确定：

**第一件装配究竟从哪一个真实物理控制步开始失去稳定性？**

区分：

- 恢复器尚未真正完成。
- 恢复器完成时物体处于不稳定状态。
- 交还时被动臂仍存在残余速度。
- Actor提出了破坏装配的动作。
- 安全投影没有正确约束该动作。
- 接触保护只在动作执行后发现问题。
- 状态机错误地取消了第一件装配保护。

### 3.2 输出确定性根因

不能只写“可能是Actor动作导致”。

必须输出：

- 第一个违反约束的控制步索引。
- 当时的原始动作。
- 实际执行动作。
- 第一件装配在执行前后的物理变化。
- 哪个安全检查没有及时阻止该动作。
- 对应源码和函数。
- 可重复的触发条件。

如果日志缺少必要字段，只允许通过同一初始条件、同一控制前缀进行定向物理复现，并补齐日志。

禁止重新随机挑选一个容易成功的场景来替代失败复现。

# 四、P0：实现装配进度保护控制器

需要真正实现一个在接触恢复、控制权交还和Actor后续执行期间持续生效的装配进度保护机制。

它不是单纯增加一个Safe_Stop判断。

## 4.1 第一件装配保护资格

当第一件装配已经通过现有严格事件判定，并满足稳定支撑和几何约束时，建立受保护状态。

保存：

- piece_1当前参考位姿。
- piece_1与base的相对变换。
- 支撑和接触关系。
- 已完成装配状态。
- 双臂抓取状态。
- 双臂末端及物体速度。
- 当前任务阶段。

不能仅因为某一时刻发生接触就标记完成。

必须使用真实完成事件和稳定性条件。

## 4.2 装配保护必须覆盖整个Actor续行阶段

保护不只在Recover_Joint中运行，还必须覆盖：

- 接触恢复执行中。
- 恢复结束稳定阶段。
- 控制权交还前。
- 交还后的Actor执行阶段。
- 随后的第二件装配操作。

只要第一件装配仍应保持完成，就不能允许后续控制器无约束地破坏它。

原有已验证的装配物体漂移、旋转及支撑限制保持不变。

## 4.3 动作执行前保护

在执行Actor提议动作前，检查：

- 该动作是否可能破坏piece_1/base的已完成关系。
- 当前B臂动作是否会向已完成装配施加不合理的接触运动。
- 当前被动臂和物体是否仍稳定。
- 该动作是否处于当前接触模式的合法运动区域。
- 当前预测的约束余量是否足够覆盖实际控制误差。

对能够安全修正的动作使用有界约束投影。

投影必须同时考虑：

- 末端运动约束。
- 物体相对位姿约束。
- 已完成装配稳定性。
- 实际接触模式。
- 抓取与夹爪状态。
- 工作空间和力限制。

**不能把“所有动作改为零动作”作为通过验收的办法。**

动作修正必须在保证安全的同时，尽可能保留Actor原本的有效任务运动分量。

如果没有经过验证的可行修正动作：

- 不执行危险动作。
- 记录明确的拒绝原因。
- 依据当前恢复资格选择再次干预或Safe_Stop。
- 不生成虚假transition。

## 4.4 动作执行后的保护

保留真实物理子步监测和动作后检查。

一旦发现第一件装配关系开始违反既定约束，按照真实物理安全流程处理。

不能等到完整Episode结束才发现装配进度丢失。

## 4.5 区分保护成功与学习成功

至少记录：

- `first_piece_protection_activated`
- `first_piece_protection_violation`
- `actor_action_original`
- `actor_action_executed`
- `action_projection_applied`
- `projection_reason`
- `projection_magnitude`
- `policy_action_accepted_unmodified`
- `post_handoff_progress`
- `post_handoff_safe_steps`

安全约束执行成功不等于Actor自主学会装配。

必须单独统计Actor未经投影的动作可行率。

# 五、P0：实现正式的Actor安全交还协议

当前V2恢复器可以交还控制权，但实际Actor续行仍可能立即破坏已有装配成果。

需要把交还过程实现为完整状态机，而不是恢复成功后直接进入Normal。

至少包含：

1. `Recovering`
2. `Recovery_Stabilizing`
3. `Handoff_Ready`
4. `Policy_Guarded`
5. `Normal`

## 5.1 Recovery_Stabilizing

恢复达到目标后，不立即交还。

必须检查：

- 主动臂位姿和速度。
- 被动臂位姿和速度。
- 正确抓取是否保持。
- 已完成第一件装配是否稳定。
- 物体相对位置和姿态。
- 接触力是否合格。
- 是否存在持续滑移或残余振荡。

所有检测基于真实物理状态。

连续满足稳定性条件后，才进入Handoff_Ready。

## 5.2 Handoff_Ready

使用当前Actor真实输出评估交还后的第一个控制动作。

如果动作可直接安全执行，则正常交还。

如果动作存在风险但能够安全修正，则使用有界动作投影进入受保护交还。

如果动作无法安全执行：

- 不允许强制交还。
- 依据当前状态资格决定重新引导、继续稳定或安全终止。
- 严格记录该次交还失败。

不能为了保证交还成功率无限期替Actor执行示范动作。

## 5.3 Policy_Guarded

交还后进入有明确结束条件的受保护阶段。

观察至少20个连续Actor动作提议。

在此期间：

- 每一步重新检查风险。
- 保护已经完成的装配。
- 保留安全动作的自主执行机会。
- 必要时允许新的真实主动干预。
- 记录所有投影、接管和拒绝事件。

20步是专项验证窗口，不代表训练中每次交还都必须强制保持20步才允许进入Normal。训练状态机可依据真实稳定性提前退出受保护状态，但必须记录实际持续时间。

如果Actor不断提出不可执行动作，不能无限依赖投影控制器伪装正常训练。

## 5.4 交还质量指标

必须分别输出：

- 恢复器目标到达率。
- 交还资格通过率。
- 实际控制权交还率。
- 交还后20步保护成功率。
- 交还后未投影Policy动作比例。
- 再次主动干预次数。
- 第一件装配进度保持率。
- Actor续行产生的实际任务进展。

其中恢复器完成、交还成功和Actor自主进展是三个不同指标，不能混合。

# 六、P0：修正被动臂保持预测低估

V2出现真实预测误差：

预测被动末端漂移1.574mm，实际漂移2.131mm。

实际值超过原2mm被动末端限制。

必须定位预测低估原因，不能只针对原始两个动作前缀加一个特例。

## 6.1 检查预测器

核查：

- 当前末端线速度。
- 当前末端角速度。
- 被动臂控制器动态响应。
- 机器人末端与持物的相对变换。
- 实际控制周期。
- OSC控制器的响应延迟。
- 当前接触状态和物体惯性。
- 预测窗口是否与实际保持窗口一致。

## 6.2 增加保守误差边界

预测安全资格不能只要求名义预测漂移小于2mm。

必须考虑模型误差：

`predicted_drift + validated_error_bound < original_safety_limit`

其中误差上界要来自实际物理校准与独立验证，不得直接把0.557mm当成对所有状态都成立的统一误差上界。

如果当前状态不属于校准过的预测域，则拒绝进入恢复。

## 6.3 验证

重新执行原始两个失败动作前缀。

增加不同速度、不同持物组合和接触前状态的定向物理场景。

要求：

- 不再允许预测安全、实际却越过原2mm限制的恢复入口。
- 被动持物仍满足3mm限制。
- 80N力限制保持。
- 没有通过增加允许漂移来获得通过。
- 预测拒绝与真实危险之间的关系有明确记录。

如果模型无法可靠预测某个状态域，则保持该状态域恢复禁用，不得默认可用。
