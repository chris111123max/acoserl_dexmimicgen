# 2026-11-01：前向抓取引导、制动余量与训练记录修复

## 依据与结论边界

父版本为 `29f35940b5801dc01ce778ead1885c76f148feda`。用户提供的是2026-10-31正式运行在约23:08的在线快照：29,697有效步、28,673次Actor/Critic更新、5,000条动态示范、949次Guide接管、507次安全交还，但两臂稳定抓取及装配均为零。原输出在新实例不可见，因此这些数字不是最终训练结果；本次没有读取或恢复那份不可见checkpoint。

源码可确认的缺口是：原普通Guide只拥有6维位姿，目标限制在首次接触前，不能提供完整闭爪抓取示范；带闭爪与稳定抓取确认的路径主要属于当前禁用的P0/P1 Recovery。动态示范满并不证明包含有效抓取经验。原健康检查也不能单独阻止“有大量干预经验但持续零稳定抓取”的训练。

以下修改针对这些缺口，不等于证明它们解释了全部训练失败。正式物理效果、稳定抓取率与吞吐必须由服务器测试给出。

## 1. 局部前向抓取Guide

新增 `grasp_guidance.py`，通过既有 `ReviewedRuntimeMixin` 接入唯一生产入口。仍是单个14维Actor、双臂独立窗口、真实示范、真实执行动作和原稀疏成功奖励。

普通位姿Guide仍仅覆盖偏离臂的6维位姿，夹爪和另一臂继续Policy。新增显式的 `forward_grasp` 阶段才拥有主动臂7维动作，包括示范夹爪指令；不得把它与普通Guide混报。

触发必须同时满足：

- 当前窗口已真实推进至记录的预抓取区间；主动臂位于相应参考附近，位置误差不超过5mm，旋转不超过0.035rad。
- 主动臂空手、没有主动接触、接触分类独立、目标物体仍处于示范拾取位姿的既有限定范围。
- 主动臂线速度不超过0.05m/s，角速度不超过0.25rad/s。
- 继续一个已经发生的普通Guide，或检测到停滞，或在示范闭爪时刻Actor没有闭爪。仅到达预抓取位置不能抢占正常Actor。

执行为局部前向参考动作加既有有界位姿反馈，直到真实闭爪、测得正确抓取和稳定持物。未测得抓取不能继续推进到搬运；稳定确认要求真实连续抓取及10步相对位姿稳定，抓取丢失清空稳定历史。

单次最多80个控制步；承接已有Guide时不重置其总预算。到位并稳定后仍须经过真实Actor动作交还，不能以目标到达替代交还。整个过程中不执行P0回退、不冻结另一臂、不直接写入中间物理状态，不启用未经资格的持物或联合接触恢复。

这是本任务对AutoSERL的抓取阶段扩展，并非宣称与官方实现完全相同。它尚未通过本次服务器MuJoCo物理验证。

## 2. 控制来源与两个Buffer

`action_provenance.py` 增加显式 `guide_gripper_owned`。`parallel_autoserl.py` 和 `ascend_data.py` 同时传递该字段，避免运行日志与Replay使用两套来源解释。

- 普通Guide：主动臂6维专家位姿，夹爪保持Policy来源。
- 前向抓取Guide：主动臂7维可被标记为专家，包括Actor恰好给出相同闭爪指令的情况。
- 另一臂仍为Policy；自身安全修正单独标记SafetyProjection。
- 纯投影不成为专家示范；部分物理步不伪造成完整transition。

Online仍保存完整真实14维动作。Demo仍由原始224条及合格动态经验组成；128 Online + 128 Demo、原始/动态96/32配额、10Q、UTD=1、n-step=3保持。专家掩码仍只是来源元数据，不引入逐臂BC损失。

采集协议升级为 `reviewed_forward_grasp_v2`。旧协议checkpoint/Replay不允许无提示混入新实验；本轮应新建独立运行。

## 3. 边界制动前瞻

原名义检查主要考虑当前控制周期轨迹和目标指令。本版还计算周期末端名义速度及下一周期的名义制动余量，避免动作本周期仍在界内，却把下周期推进到无可行制动状态。

投影新增线性制动约束，保留原物理工作空间、3mm前瞻余量和输入幅度边界。安全切向运动不应被一并归零；真正无可行动作仍拒绝。

这些都是名义OSC约束，不是非线性接触动力学证明。独立MuJoCo子步预演、真实子步检查、80N停止阈值、碰撞判断和既有2mm/3mm保持限制均未删除或提高。不能把所有拒绝都认定为误报，也不能把预测通过当作实测安全。

## 4. 停滞诊断、保存和存储

新增 `run_observability.py`：

- `live_status.json`：每约60秒、在完整采集轮结束后原子写入真实计数、阶段数据、耗时和滚动有效步/秒。
- `storage_manifest.json`：记录实际挂载、设备、路径、主机、运行标识和输出存储UUID；明确 `persistence_verified=false`。路径叫 `/data/home` 或 `testing` 不代表跨实例必然持久。
- 输出根目录下 `latest_run.json` 保存最近运行与checkpoint索引。
- 25,000有效步保存之外，默认每3,600秒在训练循环中补充完整checkpoint。停止时保留final；不删除旧checkpoint。
- 可选 `--checkpoint-mirror-root` 将完整checkpoint复制至额外外部存储，先写 `.partial` 再发布，失败保存错误收据；不覆盖旧副本。记录是否同设备，不冒称同盘副本能防卷丢失。复制开销有记录，默认不启用。
- 可选环境变量 `ACOSERL_EXPECTED_STORE_ID` 用于以后确认挂载的确是原存储，不是空的新目录。

正式训练默认在达到10,000有效步、至少32个结束回合、两臂从未稳定抓取且无装配进展时正常保存并停止，原因是 `no_stable_grasp_despite_training`。即使Dynamic Demo达到容量也不能掩盖该状态。`--no-grasp-budget` 可显式配置，0代表关闭该诊断，但Codex不得为了制造通过而调整。该诊断是运行时任务停滞判断，不是重新引入资格证书。

本修改无法找回当前实例不可见的旧目录；需要检查服务商挂载和保留策略，不能据此声称旧模型已恢复。

## 5. 效率与保持不变的项目

保留16环境并发、原视觉编码器、ResFiT学习算法、奖励及评估方式。消除每个动作对已禁用高级恢复的重复资格文件查询；扩展源码指纹在运行中缓存；跨进程自主能力统计仅在变化时广播。正常数据仍逐动作记录，避免为了速度丢掉关键证据。

数值投影增加了制动约束，实际速度未在Ascend服务器测量。不能预先宣称吞吐提高。需同时报告环境控制、网络更新、采样传输、reset、子步预演和可选副本复制开销。

## 6. 使用方法

已激活项目Ascend环境后，有界测试示例：

```bash
python -u scripts/ascend16/train.py --mode integration \
  --intervention-method independent_window --grasp-guide \
  --tag grasp_v2_seed20261032 --seed 20261032 \
  --integration-steps 2048 --integration-seconds 3600 \
  --output-root /data/home/3220251075/testing/runs/integration
```

另一seed为20261033，每组必须使用新TAG。`--no-grasp-guide`用于明确的位姿Guide对照，不得偷偷作为新方法结果。

测试通过后正式启动示例：

```bash
export ACOSERL_INTERVENTION_METHOD=independent_window
export ACOSERL_GRASP_GUIDE=1
export ACOSERL_OUTPUT_ROOT=/data/home/3220251075/testing/runs/formal
bash scripts/autoserl_baseline/launch_formal.sh guide_grasp_v2_YYYYMMDD_HHMMSS
```

先确认输出根目录在本服务器已正确挂载。正式日志现在位于 `$ACOSERL_OUTPUT_ROOT/launcher_logs/`，每次运行在 `$ACOSERL_OUTPUT_ROOT/$TAG/`。可使用nohup或已有会话工具保持断线后运行。默认checkpoint墙钟间隔为3600秒，可选环境变量 `ACOSERL_CHECKPOINT_SECONDS`；可选独立副本根目录为 `ACOSERL_CHECKPOINT_MIRROR_ROOT`。

`independent_window`仍不需要Recovery证书。未取得资格的Recovery继续关闭；不能因为P0旧证明失效阻塞本模式。不要在启动命令中附带旧 `--gate` 或 `--static-hold-certificate`。
